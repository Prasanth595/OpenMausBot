## What this does

Eight features and four deliberate fixes, built and verified end-to-end on Windows.

### 1. Windows CUA driver packaging

- `scripts/prepare-cua-win.mjs` — checksummed (SHA-256) download of the win32
  `cua-driver` package + Uniffi SDK, version-gated to the installed
  `@trycua/cua-driver`, staged outside ASAR via `electron-builder.yml`
  `extraResources` (native dll/.node must live on disk, not in the archive).
- The bundled SDK is patched for its env-var library redirect; the smoke test
  asserts the patch survived packaging.
- `scripts/smoke-cua-win-embedded.mjs` — real embedded-host start/stop, run as
  a `cua-win-smoke` leg on `windows-latest` CI.
- `electron/cua.mjs` — win32 branches (binary resolution, standalone socket,
  embedded host, platform-aware errors), reconciled with upstream's
  lifecycle/abort hardening (generation checks, socket timeouts).
- `@trycua/cua-driver`'s win32 native package moved from
  transitive-optional to a direct dependency; `pnpm-lock.yaml` reconciled.

### 2. Vision unified driver (freellmapi proxy)

- `server/drivers/vision.ts` — thin composition over
  `createOpenAIChatRuntime` (no forked protocol logic): catalog refresh,
  custom-flagged picker seeds, usage passthrough, routing-by-prefix kept
  upstream. Ships as an `access: "custom"` engine — unavailable until keyed,
  matching the grok/kimi/droid precedent.
- Full chain: config schema → env sync (`FREELLMAPI_API_KEY`/`VISION_URL`) →
  save → per-instance injection → workspace-default layering (per-instance
  config wins).
- Settings → Connections UI: API key row + base-URL field, saved through the
  OS-encrypted credential store (`visionApiKey` → `credential:set` → relay to
  `PUT /api/config`). The server reports only `vision: { configured, url }` —
  the key is never echoed.
- 8 behavioral tests against the real runtime, no mock theater.

### 3. Vision fleet model chooser (one picker for every engine)

- `server/vision-catalog.ts` — the fleet description already carries every
  engine's collected models; the chooser union is a presentation-layer view
  over those rows, not a second catalog. Vision's own row stays authoritative
  for its default and for the `rlm:*` harness models; every merged row is
  forced `custom: true` so Vision's custom-only picker renders it, and the
  `provider` badge names the engine that collected it — which is what makes a
  same-id duplicate across two engines distinguishable.
- `server/harness/registry.ts` — the fleet list is passed through
  `mergeEnginesIntoVision` on the way out, so every Vision instance reports
  its siblings' models without any driver knowing about it.
- A picked id rides to the freellmapi gateway like any other Vision model, so
  choosing an OpenCode model from under Vision needs no new routing.
- 7 tests over the merge (dedupe by id, Vision's own options first, other
  rows untouched by reference, a fleet with no Vision row passes through).

### 4. Hold-to-dictate on Deepgram Nova-3 streaming STT

- Backend comparison: ElevenLabs Scribe v2 Realtime leads on accuracy but its
  realtime WS API was too new to implement against; Whisper is chunk-based,
  not streaming; Deepgram's stable WS protocol has explicit Finalize
  semantics that map exactly onto hold-release.
- Architecture: renderer captures mic → PCM16/16 kHz mono chunks → the
  Deepgram WebSocket lives in the **main process** (the key never enters the
  renderer) → partials stream back for the live pill → release sends
  Finalize → transcript lands on the clipboard.
- Auth via `Sec-WebSocket-Protocol` (`["token", key]`) — Node's global
  WebSocket can't set headers, and this keeps the key out of any logged URL.
- `electron/dictation-stt.mjs` — pure, testable wire helpers (query builder,
  cumulative-interim accumulation, finalize handshake) + session wrapper with
  single-owner message state (no server message counted twice) and
  dead-socket recovery.
- `src/lib/clipboard-dictation.ts` — hold **Ctrl+Space** (either key order),
  Escape discards, focus-loss finalizes so the mic can never wedge open, mic
  tracks stopped on every exit path, muted audio graph. Combo purity tested
  (⌘K etc. stay free).
- Credential plumbing follows the established pattern exactly: encrypted
  store slot, config section, `OMB_DICTATION_KEY` env fallback, strip-list,
  diagnostics redaction parity. 14 tests across both new files.

### 5. Computer use for API engines (MCP toolbox + tool loop + Windows This-computer)

- `server/mcp-stdio-client.ts` — newline-delimited JSON-RPC stdio client:
  spawn → initialize handshake → tools/list → tools/call, call timeouts
  surfaced as model-visible errors, `isError` results as data not throws,
  image content blocks normalized into the shared image path, graceful
  SIGTERM→SIGKILL shutdown. Sibling `server/api-toolbox.ts` spawns every
  mounted integration's MCP server per turn and degrades one broken mount
  without losing the others (`toolListProblems`).
- `server/drivers/openai-chat.ts` gains an OpenAI-compatible tool loop for
  API-driven engines (Vision `rlm:*` etc.): advertised tools execute through
  the harness, results return as `role:"tool"` messages, screenshots ride the
  existing image bridge.
- Turn lifecycle ownership: the toolbox closes in the runtime `finally`,
  closes on synchronous dispatch refusal, is dropped when the turn mounts no
  tools, and `rlm:*` harness turns close it immediately (the harness consumes
  no tools, so mounted MCP servers must not leak — regression-tested).
- `server/index.ts` builds the toolbox **after** the browser mount so browser
  tools land in the same per-turn toolbox.
- `server/local-routing.ts`: explicit "This computer" now routes on win32
  (the bundled cua-driver ships; `shouldMountLocalComputer` covers
  darwin/linux/win32) — auto stays macOS-only.

### 6. Reverse engineering with REA (bundled skill + a catalog that survives)

- `skills/reverse-engineer-anything/` — a bundled skill the bot's own
  selector can turn on: it triggers on the words a person actually uses
  ("reverse engineer", "decompile", "ghidra", "apk", "asar", …), and it is
  gated on the `customMcp` capability, so it is only offered to a driver that
  can actually mount MCP servers. A bot that cannot mount them is never told
  to call tools that will not be there.
- The skill carries the recipe, not just the theory: how to add REA's server
  under Plugins → MCP servers (`npx -y rea-agents@latest mcp`), that the app
  resolves `npx` to the Node script it wraps so no `cmd.exe` wrapper is
  needed on Windows, which target maps to which tool, and the CLI fallback
  (`rea doctor --json`, `analyze-javascript-application`) for a machine with
  no server mounted.
- `server/env-path.ts` — npm 7+ writes its shim as
  `SET "NPX_CLI_JS=%~dp0\node_modules\npm\bin\npx-cli.js"` and runs it
  through a variable. A parser written for npm 6's shape finds nothing in the
  current one, and the shim then needs a shell to run — so the parser now
  reads both shapes and resolves the shim to the script it wraps.
- `server/api-toolbox.ts` — the per-turn cap moves from 64 to 256 tools, and
  it is a sanity cap rather than a budget: built-ins mount first and a custom
  catalog like REA's must survive whole, because its orchestration tools sit
  last and truncating it would mount a catalog nobody can use. A server whose
  argument schemas pass 64 KB is reported once with the number and the way
  out, instead of silently taxing every request.
- `server/drivers/openai-chat.ts` — an argument schema over 2 KB is
  advertised as a permissive object with a note saying so; the tool still
  validates its own arguments and its structured error goes back to the
  model, and every tool keeps its name and full description, which is what
  selection actually needs.
- Measured on this machine: REA's server mounts through the harness's own
  stdio client and advertises **207 tools**, all carrying schemas, and the
  toolbox accepts the whole catalog with zero mount problems.

### 7. Windows call transcription via Deepgram streaming STT

- The call surface now transcribes on Windows: `dictation-stt`'s open-mic
  stream emits finalized utterances (`onUtterance`) instead of only dictating;
  `main.mjs` adds call-stt start/stop/finish IPC, the preload bridge exposes
  `speechStart`/`speechStop`/`speechFinish` + the utterance event, and
  capabilities gate on Deepgram.
- `CallView` prefers the bridge on win32: renderer mic capture at 16 kHz,
  half-duplex muting while the user speaks, shared approve/question/send
  handling; the Apple Speech path is unchanged on macOS.

### 8. Voice-note dictation, "Luna" wake word, and offline built-in speech

- **Voice-note dictation** (`src/lib/voice-dictation.ts`): the composer mic
  button records on every desktop platform via the Deepgram bridge. End of
  speech is detected three ways — Deepgram's endpointer (`speech_final` via
  the new `onUtterance` bridge event), a local RMS silence watchdog, and a
  5-minute hard cap — each covering the others' failure modes. The pure event
  machine is unit-tested (23 tests across `voice-dictation.test.ts` and
  `wake-word.test.ts`); transcripts merge after typed text, never clobber it.
- **"Luna" wake word** (`src/lib/wake-word.ts`): an on-device Porcupine
  detector (renderer worker; audio never leaves the machine) starts one
  dictation session per detection; the transcript lands in the mounted
  composer through `appendComposerDraft`. Suspends while the bot speaks or a
  call owns the mic. Credential plumbing follows the established pattern:
  encrypted `picovoiceAccessKey` slot, `wakeWord.accessKey` config section,
  `OMB_PICOVOICE_KEY` env fallback, strip-list + diagnostics parity, and the
  server reports only `wakeWord: { configured }`. Settings → Connections
  gains the AccessKey row and feature toggle (`WakeWordSection`); the pill
  shows armed/listening states with live partials.
- **Offline built-in speech**: the zero-key TTS provider now exists on
  Windows, not just macOS — `server/tts/windows-voices.ts` drives SAPI
  through PowerShell (`System32\WindowsPowerShell\v1.0\powershell.exe`,
  resolved absolutely so hermetic PATHs cannot break it; utterance text
  rides in as UTF-8 base64 so nothing can break the quoting). The provider
  gate, Settings engine picker, and paired-client voice selection all open
  to win32; utterances synthesize to 16 kHz mono WAV with no key and no
  network.
- **Verification recipe**: `scripts/verify-voice.ts` (documented in
  `docs/verification/voice.md`) launches the standard isolated fixture and
  proves the wake-word credential round-trip (configured=true, write-only
  respected) and a real platform-engine WAV synthesis. On this Windows
  machine: 81,486 bytes of SAPI audio, no mocks.

### Deliberate fixes

- Reverted the `gemini`/`minimax`/`customAcp` `DEFAULT_FLEET` +
  `CUSTOM_ONLY` additions — restoring PR #30's documented removal of the
  retired Gemini CLI from the default fleet (the `minimax`/`customAcp`
  entries never existed on main and had no test or UI support).
- Added `FREELLMAPI_API_KEY`, `VISION_URL`, and `OMB_DICTATION_KEY` to
  `CREDENTIAL_ENV_NAMES` in `electron/diagnostics.mjs`, satisfying its
  drift-alarm parity test; `OMB_PICOVOICE_KEY` added to both parity lists
  (`WORKSPACE_CREDENTIAL_ENV` and `CREDENTIAL_ENV_NAMES`) in the same commit.
- Fixed the voice-note recording flow: the Apple-Speech mic button no longer
  renders simultaneously with the Deepgram stop button, and a stale wake-word
  session callback can no longer double-write a transcript after teardown.
- The browser-control extension's host allowlist was a no-op:
  `hostAllowed()` returned `true` for every host, and the check that was
  meant to be real sat in `injectableTabs()` — a function nothing called — so
  the options page's host list changed nothing at all, and only `navigate`
  even asked. Every page-scoped command now goes through one gate
  (`allowedActiveTab()`) that enforces the list the options page documents
  ("leave empty to allow every http(s) page") and refuses non-web pages
  outright. The vestigial `allowAllSites` flag, which no UI ever wrote, is
  gone. 8 tests drive the real service worker through the real command path;
  against the old worker 5 of them fail.

### Scope note

The Vision API key is configurable via instance config, env var, or the new
Settings field — matching the custom-access engine precedent. No other
Settings-UI surface was added for it beyond the key + URL row.

The REA skill needs the user to add REA's MCP server themselves; the app
never installs or registers a third-party server on the user's behalf. The
skill's own instructions say so and point at the CLI fallback, which needs
nothing but Node and npm.
